FLYRANK SEARCH INTELLIGENCE · CAPSTONE RESEARCH

Refresh Opportunity Scoring

A decision-support model for identifying content items that may deserve human review for a potential refresh.

Built on the FlyRank ML Internship dataset.

Abstract

This research asks whether search-performance signals can be used to rank content items that may deserve human review for a potential content refresh. The analysis uses the pseudonymized FlyRank warehouse and creates time-aware features from historical search performance before a defined feature cutoff. A logistic regression model is compared with a simple baseline using a held-out client-based evaluation split. The model achieved 0.623 accuracy and 0.598 ROC-AUC, compared with 0.585 baseline accuracy, while its F1 score (0.288) was slightly below the baseline F1 score (0.292). The final output is therefore best treated as an exploratory ranking and decision-support system, not as proof that refreshing a page will cause better search performance.

1. Introduction / Problem Statement

Content teams often have many pages competing for limited editorial attention. The practical question is not simply which pages perform well or poorly, but which pages show measurable signals that make them worth reviewing.

This project focuses on the Refresh / Content Opportunity Scoring lane. The decision supported by the analysis is:

Which content items should a human editor review first for a possible refresh?

The analysis produces a ranked opportunity list with reason codes so that the ranking can be interpreted rather than treated as a black-box automatic instruction.

2. Data

The analysis uses the full pseudonymized FlyRank internship warehouse release hosted on Hugging Face. DuckDB reads the hosted Parquet data without loading the complete warehouse into memory.

Tables used

  • dim_clients — client-level metadata and data availability.
  • dim_content — pseudonymized content-item information.
  • fact_daily — daily content search-performance data.
  • fact_query_90d — query-level aggregated signals.

Observed warehouse scale

104 Client dimension rows
519,606 Content dimension rows
78.8M Daily performance rows
2.4M Query-level rows

The daily warehouse covered approximately January 2025 through June 2026. The modeling design used a feature cutoff of 2026-04-30 and measured the future outcome through 2026-05-30.

Only information available before the feature cutoff was used to construct predictive features. Client names, domains, URLs, private queries and raw exports were excluded from the public research artifact.

3. Methodology

Feature design

Features summarized recent and previous 30-day search performance. These included impressions, clicks, average position, percentage changes in impressions and clicks, and derived click-through-rate signals.

The final feature table contained: 100,849 content-item/client observations.

Outcome definition

A candidate refresh_opportunity label was defined from the relationship between recent performance and the subsequent 30-day outcome. The candidate label contained 43.6% positive observations.

Validation design

The modeling data was divided using a client-based held-out evaluation design. There were 92,501 training observations and 8,348 test observations, covering 30 training clients and 14 test clients.

Model

A logistic regression classifier with standardized numerical features was used as a simple, interpretable predictive model.

Baseline

A simple baseline prediction was evaluated on the same test split so that the model's performance could be judged against a non-model benchmark.

Leakage check: Predictive features were constructed from information available before the feature cutoff, while the outcome was measured in the subsequent window.

5. Limitations & Honest Framing

  • This analysis identifies patterns and ranks content items for decision support; it does not prove that refreshing a page will cause its search performance to improve.
  • The results describe associations observed in the FlyRank internship dataset and should not be interpreted as evidence about Google's ranking algorithm or as causal evidence of refresh impact.
  • The warehouse is pseudonymized, so the analysis cannot provide public client names, domains, URLs, or private search queries.
  • The refresh opportunity score depends on the chosen features, target definition, time windows, and validation design.
  • Pages ranked highly should therefore be reviewed by a human editor rather than automatically refreshed.
  • The model may perform differently on future data or on clients and time periods that differ from the evaluation sample.
